1. 背景与目标
1.1 现状
Helios 是目前最快的表面码 FPGA 解码器之一：在 VCU129 上实现了分布式 UF 解码器，d=21
（唯象噪声）平均 11.5ns/轮，d=17（电路级噪声）平均 23.7ns/轮；借助上下文切换（Helios-
n）可在同板解码 d=51。它支持加权边、擦除错误、滑动窗口（2d 高窗口批量解码 + 提交旧 d
层）三种扩展。
Snowflake 是 UF 家族的最新发展：把 UF 改造成流式（streaming）解码器。相对 UF 精度提升
约 25%（逻辑比特寿命 +24.9(5)%），平均运行时间标度从 UF 的略高于立方降为亚二次方；窗口
高度从 2d 减为约 d（处理器数量减半）；核心创新是 frugal 方法（窗口逐轮上移、计算零丢弃）
与 2:1 簇生长调度（half-edge 生长 + whole/half 簇记账）。
1.2 目标

=== PAGE 2 ===
在 Helios 现有 RTL 基础上实现 Snowflake 算法，期望获得：
1. 精度：比 UF（即 Helios 现行算法）高约 25% 的逻辑比特寿命；
2. 面积：PE 阵列减半 + 删除 direct-channel 消息网络；
3. 流式语义：逐轮提交纠错（correction），天然适配实时 QEC；
4. 时钟频率：所有通信退化为邻居链路，缓解 Helios 3D→2D 布线瓶颈。
1.3 总体结论
可行，且契合度高。 Snowflake 的分布式实现沿用 Macar/Actis 的"一节点一处理器 + 一边一链路"架构，
与 Helios 同源（Snowflake 论文将 Helios 列为第一个本地化 UF 实现）。改动集中在 PE 数据通路与控制
器状态机；Helios 的 PE 阵列组织、邻居链路、全局同步、控制树、上下文切换、多 FPGA 分区机制均可复
用。

5.4 drop 的实现（关键决策，见 §6.1）
方案 A（推荐）：沿 K 轴移位寄存器。每个 PE 在 drop 拍把相对变量
（CID/defect/pointer/whole/grown/correction…）发给下层 PE、接收上层 PE 的，经现有垂直
邻居链路完成。静态 ID 语义不变（顶层 ID 最小），unrooting 逻辑原样照搬。
方案 B（备选）：层映射旋转（ring pointer），物理 PE 不动、逻辑层号轮转。省布线但破坏静态
地址假设，unrooting 语义需重构。
5.5 提交路径
correction 位随缺陷移动即时翻转；drop 时把最底层 PE 的 owned 边 correction 串行移出 → 逐
轮纠错输出流。替代 Helios 的批量结果计算路径（get_boundry_cardinality_3d 可退役或改为统
计逻辑翻转的流式累加器）。
5.6 多 FPGA 分区（partitionScheme.py / hub-leaf 复用）
Snowflake 垂直操作天然串行，垂直方向仅"下坠一层"一条边界流量 → 沿 K 轴切分最自然：每个
leaf 管若干连续层，跨界只需最底/顶两层间的邻居链路。
direct channel 退役后跨 FPGA 流量比 Helios 现状更小；hub 树 + routing_table +
final_arbitration 复用。
5.7 直接复用的 Helios 资产
加权边：Snowflake 的"半条边"与 Helios 整数权重天然兼容——权重刻度 ×2（neighbor_link
的 LENGTH=2·w 已有该语义）。Snowflake 论文 future work 点名的加权生长，Helios 已实现。
上下文切换（Helios-n）：Snowflake 窗口高度减半后，同样 d 所需 PE 更少；叠加 context
switching 可进一步换面积/增大 d。
控制树 / 全局同步 / 死锁检测 / serdes / 互连模型 / AXI 主机接口 / 随机错误注入：全部不变。
