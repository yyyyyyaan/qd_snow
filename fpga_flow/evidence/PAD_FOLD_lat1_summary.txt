P0'  FOLDING EXPERIMENT -- evidence summary
==========================================
Question: a shared-lattice array instantiates ONE datapath per SLOT.  A rotated
surface code's check lattice fills only HALF of its own bounding box (d21:
bbox 22x20 = 440 slots, 220 real -- fpga_flow/logs/rotated_slots.txt).  Does a
slot that is never valid in any context cost area after synthesis, or is it
folded away?  This decides whether the measured ~2x graph-size advantage of the
rotated code (fpga_flow/logs/pricing_rotated.txt) turns into real area.

Method: `fpga_flow/make_lattice_sim.py --pad K` multiplies the SPATIAL box by K
(P -> K*P, so NSLOT/ESLOT x K) and sets `*_VALID = 0` in EVERY context for the
added slots.  The layer window GMAX is untouched, so every real cell keeps its
(layout layer, rank), its address formula and all four address-band assertions.
The RTL is NOT touched.  Driver: fpga_flow/pad_fold_battery.ps1 (serial, one
Vivado at a time); part xcvu9p-flga2104-2L-e, period 5.0 ns, -Mode synth.
Each K lands in its own tag / log / report / CSV row (`lat1_pad<K>_...`).

  -> instances x4, LUT +208 (+4.8%), FF -18, timing slightly BETTER.
  -> the whole +208 lands in the FIRST doubling (62 -> 124 instances: +199);
     the SECOND doubling (124 -> 248 instances, the same number of added
     instances) costs +9 LUT.  Cost is therefore NOT proportional to the number
     of dead instances -- it is a one-time perturbation of the live slots'
     constant-folded read map (per-instance LUT deltas have both signs,
     -18 .. +38; the address space went 744 -> 1488 -> 2976 words, AW 10 -> 11
     -> 12, so every live cell's constant bank addresses changed).
  -> NB this one-time width/permutation effect does NOT apply to the rotated
     build: its slot space (440) is the same size as the unrotated one (462),
     so it pays no address-width penalty at all -- only its FILL halves.

6. VERDICT
----------
Folding HOLDS (the pre-registered rule was: LUT/FF ~ unchanged -> dead slots
fold -> the rotated ~2x is real; LUT/FF ~ K x -> dead slots cost full price).
A never-valid slot has no state registers (`own`/`omir`/`eown` are declared
inside `generate if (*_VALID)`, snowflake_pe_array_lat1.sv:424/618) and no write
enable (`run` = NVALID/EVALID && ...), so only combinational logic remains, its
outputs are unread, and Vivado deletes the instance.

  area scales with LIVE cells, not with instantiated slots
    -> unrotated d21: 462 slots/layer, ALL 462 real (verified:
       check_lattice_slots.py surface 21 7, box 21x22, 0% waste), 9,702 graph nodes
    -> rotated   d21: 440 slots/layer, 220 real (50% fill), 4,620 graph nodes
    -> factor 2.10x on nodes, 1.97x on graph edges (100,038 -> 50,838)
  => Z-7020 d7: 72,982 -> ~37K LUT (137% -> 70%)
  => circuit-level d21 inside ONE VU9P: ~1.1M -> ~560K LUT (Helios: n/a)
