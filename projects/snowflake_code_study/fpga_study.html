工程概览

先回答三个问题：它是什么、现在做到哪、代码在哪里。

一句话

它是 localuf 参考解码器的逐拍 RTL 镜像：算法真值始终在 Python（localuf-main/），RTL 只负责在全局同步的节拍里逐拍复现它，并用逐行相等的轨迹证明自己没错。

量子芯片每轮测量 → syndrome 比特流
PS / 上位机写 syndrome、start，读回轨迹
PL：Snowflake 阵列窗口上移 → 生长 → 合并 → 提交
commit_onehot本轮要翻转的 commit 区边
Pauli frame只记账，不物理施加

“分布式”指顶点级并行（每个节点一个 PE、每条边一个模块），不是多 FPGA。论文明确说过：I/O 引脚与几十纳秒的跨片延迟不允许把一张解码图拆到多片。

02

五分钟心智模型

四条直觉建立之后，读 800 行阵列代码不会迷路。

① 图先于 RTL

解码图（顶点 = 探测事件，边 = 独立错误机制）由 generate_snowflake.py 从 localuf 对象导出，不是手写。RTL 里没有一处硬编码码距：节点数、边数、方向数、指针位宽、簇号位宽全是生成头里的 localparam。同一个 RTL 通过换头文件覆盖 rep / surface / rotated 的多种 d（本机构建到 d3/d5；d7 受 elaboration 内存墙限制，d21 只有 VU9P 外推）。

② 一个逻辑 step = 算法的一个 timestep

全阵列只有一个 stage[2:0] 广播给所有 PE 和边。没有 per-PE 状态机、没有握手。每个单元只回答“我这一拍还会不会变”（组合 busy_c），控制器把全阵列或起来；为 0 就进入下一阶段。平面阵列一拍就是一个 timestep；共享晶格把每个 timestep 展开成 NCTX 个 phase 拍（每个上下文一拍），轨迹仍按逻辑 step 记一行。阶段时长是数据相关的，这正是轨迹里 step 数会变的原因。

③ 窗口上移 = DROP 拍“向上拉”

流式解码每轮把窗口上移一层：底层提交出去、整体下移、顶部注入新测量。扁平核“写下去”，阵列版必须“从上拉”——一个 PE 不能写别人的寄存器。于是生成器额外导出 SNOW_NODE_ABOVE，DROP 从上方节点拉取状态，并做 SNOW_CID_DELTA 重映射。

④ 共享晶格 = 每槽一路数据通路

窗口沿时间轴切成 NCTX 个上下文（切片）。状态按 (槽, 切片) 存在寄存器堆里，逻辑数据通路只有一份，每个 phase 服务一个切片。代价是 merging 必须走两趟：pass A 洪泛写 pb，pass B 同步比较 bank 指针。

算法侧只需要记住三件事 生长：一条边由两端各推半条，growth 饱和到 2，所以只有 0/1/2 三态。合并：缺陷沿指针逐边上推，两个缺陷相遇异或抵消；簇根用最小节点 ID 当代表元。调度：2:1 调度把“长整簇”和“长半簇”分两轮，避免两个簇在半条边距时互相过冲。

一轮里发生什么

阶段字符做什么何时结束
ST_DROPD窗口上移：从上方节点拉状态、CID 重映射、清顶层、异或新 syndrome；边也继承上方的 growth/ecorr固定 1 个 phase 扫完（每槽每上下文一次）
ST_GWG生长“整簇”：active && whole 的节点发 pulse，翻转 whole，置 grown；底层含 'D' 指针的节点去根化固定 1 个 phase 扫完
ST_MWM合并（整簇轮）：洪泛找更小 cid → 改指针；同步继承 active、沿指针 push 缺陷；两路 push 异或抵消全阵列 busy 为 0，且 step > 1（BUSYREG 守卫）
ST_GHg生长“半簇”：active && !whole && !grown 的节点发 pulse，whole ← 1固定 1 个 phase 扫完
ST_MHm合并（半簇轮）：同上；1:1 模式在这里直接 done全阵列 busy 为 0

轨迹里的 T <round> <stage> <step> 就是这张表的直接投影。rotated d3 唯象的每轮拍数是 16/20/20/28/28/28/20/28/20/28/28/20（直连阵列口径；板级 CYC_LAST 少 1，计数口径差别已写死在寄存器注释里）。

wire mrg_running = (stage == ST_MW) || (stage == ST_MH);
wire [1:0] m_pass_w = (mrg_running && any_run)
                    ? (lat_bpass ? 2'd2 : 2'd1) : 2'd0;

ST_MW: if (stage_last) begin
  // BUSYREG 构建下这里还有 && (step_cnt > 1) 的守卫
  if (!any_step_busy) begin
    if (ONE_ONE) begin stage <= ST_IDLE; step_cnt <= 0; done <= 1; end

  end else step_cnt <= step_cnt + 1;

为什么必须两趟：平面阵列里，消费者读的是邻居组合的 push。合并成一路数据通路后，一个格无法再“戳”晚于自己相位的邻居。于是 pass A（洪泛）把推送决定压成状态位 pb 写进 bank；pass B（同步）再比较 bank 里的指针，算出 push 和 active。边只在 pass B 提交（edge_en），因为只有那时 bank 指针才是本步的。

这不是风格问题。写成 bview[myaddr]（myaddr 是 wire）会告诉 Vivado “这是一个可变地址的存储”，于是每个读口都生成整 bank 的 mux：surface d3、744 字 × 576 个读口，25 分钟综合不完。写成“每上下文一个常量地址 + phase 选择”后，硬件就是一个 NCTX 选 1 的寄存器 mux。镜像规则同样重要：源的切片早于当前 phase ⇒ 读 mirror（它在 pass 开始时已提交完），否则读 register；偏移必须截断到 AW 位（生成器把负偏移掩成模 2AW）。

三条硬契约与七个坑

这些不是“注意事项”，是已经被测量惩罚过的结构性约束。

单时钟 · 无 CDC

clk 是 PL 里唯一的时钟；板上用 PS 的 FCLK_CLK0，它同时给 M_AXI_GP0 计时。唯一的异步输入是 pl_reset_in，在 PL 内同步。trace 放在 PL 里抓、PS 事后取，正是为了避免“降频单步”引入第二时钟域。

复位是唯一路径

state bank 没有 initial 镜像：write_verilog -mode funcsim 会丢掉它；有镜像时 Vivado 还会认为时钟复位冗余并优化掉，门级从 x 起跑、永不收敛。所以 reset_sync 是阵列 reset 的唯一驱动，且计数器 INIT=0 保证上电自复位。

initial cnt = 16'd0;
always @(posedge clk) sr <= {sr[SYNC-2:0], arst_in};
wire req = sr[SYNC-1] | sw_reset;
always @(posedge clk) begin
  if (req) cnt <= 0;
  else if (cnt < LEN) cnt <= cnt + 1;
  core_rst <= req | (cnt < LEN);
end

观测窗口 = 接口

cap_en = armed & (running | done)，记录只在 dbg_valid（stage_last）那一拍写入。MAXREC 必须是 2 的幂，因为写指针靠位宽截断回绕；非 2 的幂会算错地址。溢出由 STATUS[2] 锁存，不静默丢数据。

术语表

按“算法 → 架构 → 时序 → 板级”排序。
syndrome（综合征）
辅助比特每轮测量的差分；1 bit = 1 个探测器被触发。上游电路的输出，本设计的输入。
decoding graph（解码图）
顶点 = 探测事件，边 = 可能引起该翻转的独立错误机制；两个空间轴 + 时间轴。
defect（缺陷）
被触发的探测器在图上形成的“粒子”；沿指针逐边上推，两个相遇异或抵消。
cluster（簇）
由生长边连通的节点集合；用簇内最小节点 ID 当代表元 cid。
pointer（指针）
每个节点指向“父节点方向”的编码；根节点为 C，指向下方为 D 类方向。
half-edge growth（半边生长）
一条边由两端各推半条；growth 加 2 饱和，所以只有 0/1/2 三态。
2:1 schedule
生长分两轮：先长“整簇”（whole），再长“半簇”；避免两个簇在半条边距时互相过冲。
unrooting（去根化）
窗口上移时根被挤出窗口底部；把指针树重置，让簇以新的最小 ID 为根。
commit region
窗口底部 c 层；其纠错结果已经安全，可以输出 commit_onehot。
window / slice
流式解码一次保留约 d 层；共享晶格再沿时间轴切成 NCTX 个切片（上下文）。
context（上下文）
一个逻辑解码轮对应的一份状态；多个上下文分时复用同一套物理数据通路。
shared lattice（共享晶格）
整个窗口共用一张 (槽 × 上下文) 寄存器堆；逻辑通路只一份，每拍服务一个 phase。
phase
当前正在服务的上下文编号；状态 bank 的地址 = (槽, 切片)，由 phase 选择。
two-pass merging
共享晶格下 merging 必须分两趟：pass A 洪泛写 pb，pass B 同步比较 bank 指针并提交边。
mirror
每个 bank 单元的第二份寄存器；存“本趟开始时”的值，供晚相位消费者读取。
quiescence（静默）
全阵列没有任何单元“这一拍会变”；FSM 用它结束数据相关阶段。
line-exact（逐行等价）
RTL 轨迹与 localuf 黄金逐行相同，包括每拍状态和提交事件；本项目的唯一正确性判据。
golden trace
由 localuf 跑同一 12 轮激励生成的参考文本；T/N/E/P 四类行。
negative control（负对照）
故意做错的实现，用来证明判据本身能失败；每条 PASS 都配一条应 FAIL 的对照。
OOC
out-of-context 综合/实现：只对顶层模块及其子模块跑，不接板级 IO，用来量面积与时序。
WNS
worst negative slack；≥0 表示满足目标周期。本设计 Z-7020 @20 ns 为 +0.350 ns。
AXI4-Lite
轻量内存映射总线：5 个通道、单 outstanding；PS 用它读写寄存器，不传流式数据。
ID block
0x034–0x064 的自描述寄存器组；软件在读结果前先证明 bitstream 的配置。
CDC
clock domain crossing；本设计单时钟、无 CDC，唯一的异步输入是复位。
